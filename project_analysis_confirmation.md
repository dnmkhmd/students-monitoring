# Подтверждение анализа проекта «Students Monitoring» (Tulekter)

Я успешно проанализировал структуру и файлы вашего проекта. Ниже представлен краткий обзор архитектуры и механизмов, которые я изучил.

## 1. Архитектура проекта

Проект представляет собой клиент-серверное веб-приложение:

### Frontend (React 19 + TypeScript + Ant Design)
- **Структура**: `src/components/`, `src/services/`, `src/types/`, а также файлы локализации (i18n.ts) и основной роутинг в `App.tsx`.
- **Компоненты**: Включают в себя страницы логина (`LoginPage`), таблицы студентов (`StudentTable`), вакансий (`VacanciesPage`), обратной связи (`FeedbackPage`), и страницу профиля пользователя (`ProfilePage`).
- **Роутинг**: Настроен с помощью `react-router-dom` в `App.tsx`.
- **Стилизация**: Используется библиотека компонентов `Ant Design`, а также иконки `lucide-react` и `@ant-design/icons`.

### Backend (FastAPI + Python)
- **Основные файлы**: 
  - `main.py`: Основной файл с инициализацией FastAPI приложения, конфигурацией CORS и эндпоинтами.
  - `models.py`: ORM модели SQLAlchemy (`StudentsInformation`, `User`, `Vacancy`, `Feedback`).
  - `schemas.py`: Pydantic схемы для валидации входных и выходных данных.
  - `auth.py`: Логика безопасности (JWT токены, хэширование bcrypt).
  - `database.py`: Настройка подключения к базе данных через SQLAlchemy.

## 2. Хранение и использование роли пользователя

- **На Backend**: Роль пользователя (например, `admin`, `viewer`, `student`) хранится в таблице `users` в базе данных. При успешном логине (`/login`), сервер возвращает JWT `access_token` вместе с полем `role`. Авторизация защищенных маршрутов осуществляется с помощью `Depends(auth.get_admin_user)` и `Depends(auth.get_current_user)`.
- **На Frontend**: 
  - **Хранение**: После успешной авторизации (`LoginPage.tsx`), роль пользователя, email и токен сохраняются в `localStorage`: 
    `localStorage.setItem('userRole', userRole);`
    `localStorage.setItem('token', access_token);`
  - **Использование**: Роль извлекается из `localStorage.getItem('userRole')` и используется для условного рендеринга (например, отображения кнопок «Добавить/Удалить» только для `admin`), а также для ограничения доступа к определенным страницам (как мы сделали в `ProfilePage` с PIN-кодом для не-администраторов).
