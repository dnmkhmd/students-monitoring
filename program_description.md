# Описание программы «Students Monitoring» (Tulekter)

## 1. Как работает сама программа

Программа представляет собой веб-приложение для учета, управления и мониторинга информации о студентах (или выпускниках). 
Она работает по клиент-серверной архитектуре:
* **Бэкенд (Серверная часть):** Написан на языке Python с использованием скоростного фреймворка **FastAPI**. Он отвечает за связь с базой данных (через SQLAlchemy), обработку бизнес-логики и предоставление REST API (маршруты для получения, добавления, изменения и удаления записей).
* **Фронтенд (Пользовательский интерфейс):** Написан на **React** с использованием TypeScript и библиотеки компонентов **Ant Design**. Он делает запросы к бэкенду и отображает данные в удобном виде.

Взаимодействие происходит в реальном времени: когда пользователь добавляет студента или меняет его данные, фронтенд отправляет запрос на сервер, сервер обновляет базу данных и возвращает ответ, после чего таблица на экране пользователя мгновенно обновляется.

---

## 2. Полезные функции, которые упрощают работу

Приложение включает в себя множество инструментов для удобной работы с большим объемом данных:
1. **Умный поиск (Live Search):** Позволяет мгновенно искать студентов по ФИО, ИИН, серии документа или городу/региону без необходимости перезагрузки страницы.
2. **Фильтрация и Сортировка:** Можно отфильтровать список по определенной категории (например, показать только «Бакалавров» или «Магистров»), а также отсортировать таблицу по ФИО или ID.
3. **Пагинация (Постраничный вывод):** Данные разбиты на страницы (по умолчанию 10 записей), что ускоряет загрузку страницы и не перегружает интерфейс.
4. **Экспорт данных:** Присутствует возможность выгрузки текущего списка студентов в отдельный файл (Excel/CSV), что очень полезно для отчетности (компонент `ExportButtons`).
5. **Всплывающие окна (Модалки):** Добавление, редактирование и просмотр полных данных о студенте происходит во всплывающих окнах (`StudentForm` и `StudentDetails`), поэтому пользователю не нужно переходить на другие страницы. Ошибочные удаления предотвращаются предупреждающим окном подтверждения.

## 3. Описание главной страницы

Главная страница выполнена в стильном и минималистичном дизайне (фреймворк Ant Design) и состоит из следующих ключевых блоков:

* **Верхняя панель (Header):** Содержит темный фон с логотипом и названием приложения — **«🎓 Tulekter»**.
* **Боковое меню (Sidebar):** Панель навигации слева, где в данный момент находится активный раздел **«Студенттер»** (Студенты). Это закладывает основу для будущего масштабирования (можно добавить пункты «Статистика» или «Настройки»).
* **Рабочая область (Main Content):** Основная часть экрана, которая включает в себя:
  * **Заголовок и Статистика:** Показывает общее количество студентов в базе и количество найденных записей по текущему запросу.
  * **Панель инструментов:** Удобная строка поиска, кнопка экспорта данных и выделенная синим цветом кнопка **«+ Добавить студента»**.
  * **Главная таблица:** Содержит столбцы: `ID`, `ФИО`, `ИИН`, `Категория` (с цветными тегами, например синим для заполненных полей), `Город/Регион` и `Действия`.
  * **Кнопки действий (Actions):** Напротив каждого студента есть три аккуратные иконки: 
    * 👁️ **Просмотр** (детальная информация, открывает карточку студента), 
    * ✏️ **Редактировать** (открывает форму заполнения данных), 
    * 🗑️ **Удалить** (удаление записи, красная иконка корзины).

## 4. Регистрация и Авторизация: Текущее состояние и Идеи

**Текущее состояние:**
На данный момент в программе **нет системы регистрации и авторизации**. Любой пользователь, имеющий доступ к ссылке на приложение, может просматривать, добавлять, удалять и изменять данные студентов (в бэкенде нет проверки токенов, а фронтенд сразу пускает на страницу таблицы).

**Идеи и план по внедрению логина/регистрации:**

Если программа будет использоваться в учебном заведении (или организации), система безопасности крайне необходима. Вот как это можно реализовать:

1. **Создание системы ролей:**
   * **Администратор (Admin):** Имеет все права — может добавлять, изменять и удалять записи.
   * **Наблюдатель (Viewer):** Имеет доступ только к просмотру таблицы и экспорту данных (кнопки удаления и изменения скрыты).

2. **Как будет совершаться вход:**
   * При открытии сайта пользователя должна встречать страница **Входа (Login page)** с формой для ввода Email и пароля. Пока он не авторизуется, к таблице студентов не будет доступа (Private Routes в React).
   * Для новых сотрудников можно сделать кнопку **«Зарегистрироваться»** или (что безопаснее) администратор будет сам создавать аккаунты новым работникам.

3. **Техническая реализация (через JWT токены):**
   * **Бэкенд:** В базе данных (SQLAlchemy) создается новая таблица `users` (id, email, hashed_password, role). Создаются два новых пути: `/register` и `/login`. Пароли обязательно шифруются библиотекой `passlib` (bcrypt).
   * **Процесс:** Пользователь вводит логин и пароль. Если данные верны, бэкенд отдает специальный ключ доступа "JWT токен". Фронтенд (React) сохраняет его в `localStorage` браузера и прикрепляет к заголовкам (`Authorization: Bearer <token>`) при последующих запросах. Если токена нет или он устарел — сервер не отдаст список студентов и вернет ошибку 401 Unauthorized, а фронтенд вернет пользователя на страницу входа.
